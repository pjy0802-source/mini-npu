# Mini NPU Simulator

3×3 패턴과 필터의 같은 위치에 있는 숫자를 곱한 뒤 모두 더해 MAC 점수를 계산하는 Python 실습입니다.

## 실행 방법

```powershell
python main.py
mini npu simultor 시작
십자가 필터 점수: 5
```

## 1단계 실습

십자가 패턴과 십자가 필터를 각각 2차원 리스트로 만들었습니다.
두 배열의 같은 위치를 곱해서 더하면 실행 결과는 5입니다.
## 2단계 실습

같은 십자가 패턴을 X 필터와 비교한 결과 1점이 나왔습니다.
두 배열에서 모두 1인 위치는 가운데 칸 하나였습니다.

같은 십자가 패턴을 두 필터와 비교한 결과, 십자가 필터는 5점, X 필터는 1점이었다.
## 3단계 실습

십자가 필터는 5점, X 필터는 1점이 나왔다.
십자가 필터의 점수가 더 높아서 프로그램은 `십자가`로 판정했다.
두 점수의 차이가 `1e-9`보다 작으면 동점으로 보고 `판정 불가`를 출력하도록 했다.
## 4단계 실습 — MAC 계산 함수 만들기

십자가 필터와 X 필터의 점수를 구하던 두 반복문을 `mac()` 함수 하나로 합쳤다.
같은 패턴에 필터만 바꿔 함수를 두 번 호출했다.

- 십자가 필터 점수: 5
- X 필터 점수: 1
- 최종 판정: 십자가

함수로 바꾼 뒤에도 기존과 같은 점수와 판정이 나오는 것을 확인했다.
## 6단계 실습 — 필터 A와 B 입력받기

`read_matrix()`를 재사용해 필터 A, 필터 B, 패턴을 순서대로 입력받았다.
A에 십자가, B와 패턴에 X를 입력한 결과 A는 1.0점, B는 5.0점으로 B가 선택됐다.
## 7단계 실습 — MAC 연산 시간 측정

3×3 패턴과 필터 A의 MAC 연산을 10회 측정해 평균 시간을 ms로 출력했다.
입력과 출력에 걸린 시간은 측정에서 제외했다.
필터 하나의 점수를 계산할 때 3×3의 모든 칸을 방문하므로 MAC 연산은 9회다.
## 8단계 실습 — 실행 모드 선택과 JSON 파일 읽기

실행 메뉴에서 `1`을 선택하면 3×3 수동 입력 모드가 실행되고,
`2`를 선택하면 `main.py`와 같은 폴더의 `data.json`을 읽도록 구성했다.

`json.load()`로 파일을 읽은 결과, 필터 그룹은 `size_5`, `size_13`,
`size_25`였고, 패턴은 총 6개였다.

처음에는 `data.json`이 실습 폴더에 없어 `FileNotFoundError`가 발생했다.
파일을 `main.py`와 같은 폴더에 복사한 뒤 정상적으로 읽히는 것을 확인했다.

## 9단계 실습 — 첫 번째 JSON 패턴의 MAC 점수 계산

`size_5_1`의 입력 패턴을 꺼내 같은 크기의 `size_5` 필터 그룹을 선택했다.
기존 `mac()` 함수를 재사용해 Cross 필터와 X 필터의 점수를 각각 계산했다.

- Cross 점수: `0.9`
- X 점수: `0.8999999999999999`
- JSON에 기록된 기대 라벨: `x`

두 점수의 차이는 `1e-9`보다 작다.
이 단계에서는 점수와 기대 라벨을 확인했고, 동점 판정과 PASS/FAIL 비교는 다음 단계에서 구현한다.
## 10단계 실습 — 라벨 정규화와 PASS/FAIL 판정

기대 라벨 `+`와 `x`를 각각 `Cross`와 `X`로 변환했다.
`size_5_1`은 두 점수의 차이가 `1e-9`보다 작아 `UNDECIDED`로 판정됐다.
기대 라벨 `X`와 판정이 달라 `FAIL`로 표시됐다.
## 11단계 실습 — JSON 패턴 일괄 검사

패턴 이름에서 크기를 읽어 해당하는 필터 그룹을 선택했다.
전체 6개 패턴을 검사해 3개가 통과했고, 3개는 동점으로 판정되어 실패했다.
실패 케이스는 `size_5_1`, `size_13_2`, `size_25_1`이다.
## 12단계 실습 — JSON 데이터 검증과 실패 사유 기록

패턴 이름, 같은 크기의 필터 그룹, 행과 열의 개수, 숫자 값, 기대 라벨을 검증했다.
필터 키 `cross`와 `x`는 프로그램 내부의 `Cross`와 `X`로 변환했다.
잘못된 패턴 이름으로 테스트한 결과 해당 케이스는 실패 사유를 표시했고,
나머지 패턴은 계속 검사했다. 원본 데이터의 동점 3건도 요약에 사유를 표시했다.
## 13단계. 크기별 MAC 성능 비교하기
## 결과 리포트

`python main.py`를 실행하고 `2`를 선택해 원본 `data.json`을 검사했다.
전체 6개 중 3개가 통과했고, 3개가 실패했다.

### 실패 원인 분석

| 케이스 | 기대 라벨 | 실제 판정 | 점수 차이 |
|---|---|---|---:|
| `size_5_1` | X | UNDECIDED | `1.11e-16` |
| `size_13_2` | Cross | UNDECIDED | `2.66e-15` |
| `size_25_1` | X | UNDECIDED | `1.78e-15` |

1. 원본 데이터의 세 실패는 모두 동점 판정에서 발생했다.
2. `0.1` 같은 일부 소수는 이진 부동소수점으로 정확히 표현할 수 없다.
3. MAC에서 곱셈과 덧셈을 반복하면 이 근사 오차가 최종 점수에 남을 수 있다.
4. `size_5_1`에서는 Cross가 `0.9`, X가 `0.8999999999999999`로 계산됐다.
5. 두 점수의 차이가 `1e-9`보다 작으면 `UNDECIDED`로 판정한다.
6. 세 케이스의 기대 라벨은 `Cross` 또는 `X`이므로 `UNDECIDED`가 나오면 FAIL로 집계한다.
7. 기대 라벨 `+`와 `x`를 `Cross`와 `X`로 바꿔 표기 차이가 비교 결과에 영향을 주지 않도록 했다.
8. 데이터 형식 검증을 위해 `size_5_2`를 잠시 `wrong_key`로 바꿨다. 해당 케이스만 키 형식 오류로 처리됐고 이후 케이스도 계속 검사됐다. 테스트를 마친 뒤 원래 키로 복원했다.

### 성능 측정과 시간 복잡도

| 크기 | 평균 시간(ms) | 필터 하나당 MAC 횟수 |
|---|---:|---:|
| 3×3 | 0.002580 | 9 |
| 5×5 | 0.003040 | 25 |
| 13×13 | 0.023850 | 169 |
| 25×25 | 0.046090 | 625 |

1. 각 크기에서 MAC 함수 호출을 10회 측정해 밀리초 단위 평균을 구했다.
2. 행렬 생성, 파일 읽기, 화면 출력은 측정 구간에서 제외했다.
3. N×N 행렬은 N개의 행에서 각각 N개의 칸을 방문하므로 필터 하나당 MAC 횟수는 N²이다.
4. 필터 두 개를 비교할 때는 총 2N²번의 MAC이 필요하므로 시간 복잡도는 O(N²)이다.
5. 이번 실행에서는 3×3에서 25×25로 커질 때 연산 횟수는 약 69배, 평균 시간은 약 18배 늘었다.
6. 작은 행렬에서는 함수 호출과 반복문 준비 비용의 비중이 크다. 실행 환경과 시스템 부하도 측정 시간에 영향을 준다.
